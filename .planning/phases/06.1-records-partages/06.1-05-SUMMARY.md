# Phase 6.1 Plan 05: Shared records wiring and evidence Summary

The hosted build now shares adventure scores and level times through `api/records` without ever waiting on the
network: `main.ts` keeps `zuma.records.v1`, queues the `record-score` effect and won pack-level times, synchronises at
load, on `online` and after each level, imports the device's existing records once (D-08), shows the best time with its
holder and the differing personal best in the STATS, and the « TOUS » / « MOI » tables on the adventure and ending
plaques (toggled by a click or tap on RECORDS). The standalone and `npm run dev` stay local with the profile's first
name beside the best time. Proven end to end under Node against the generated worker on SQLite, and at DPR 2 in
Chromium against a proof server that runs the same generated worker.

**3. [Rule 3 - Blocking] Standalone single file was a SyntaxError since 06.1-01**
- **Found during:** Task 3 (standalone evidence: blank boot screen, « Invalid or unexpected token »)
- **Issue:** `tools/build.mjs` inserted the bundle with `html.replace(regex, \`…${js}…\`)`. `records.js` contains `'^[a-z0-9-]{1,40}$'`, and in a replacement string `$'` means "the text after the match", so the rest of `index.html` was spliced into the regex literal. The r215 tests check the stripped concatenation, not the inserted HTML, so they did not catch it.
- **Fix:** the styles, the module bundle and the inlined assets are now inserted by replacer functions. A new lock in r222-wiring checks that the hazard is real and that all three insertions use `() =>`.
- **Files modified:** tools/build.mjs, tests/r222-wiring.test.mjs
- **Commits:** c2a4490 (RED), ccee6d3 (GREEN)
- `tools/build.mjs` is not one of the files the parallel 06.1-03 executor edits (`tools/deploy.mjs` and the deploy tests).

**4. [Planned adjustment] ADV_SCOPE.ending 164 → 162**

- **Commits:** d0fb743, 52f1dec
